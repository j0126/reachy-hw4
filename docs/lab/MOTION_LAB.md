# Reachy HW4 Motion Lab

모션 재생, MuJoCo 미리보기, R1–R3 실험(MuJoCo·실제 로봇), 추종 성능 확인, 결과 비교와 보고서 자료 내보내기를 하나의 PySide6 창에서 한다.
화면은 **① 모션 · ② 실험 · ③ 결과** 탭 세 개뿐이다 (2026-11-12 정리, §2.1).
**실제 로봇: 창 위쪽 로봇 상자에서 사람이 직접 조작한다** (2026-11-12 사용자 결정, CLAUDE.md 규칙 3). 누른 버튼의 동작만 실행된다 ([GUI_ROBOT.md](GUI_ROBOT.md)).

## 1. 실행

```
.venv\Scripts\python -m reachy_motion gui
```

- 창 제목: `Reachy HW4 Motion Lab - <모션>`. ① 모션 탭에서 시작한다.
- 화면 문구는 한국어다(`reachy_motion/gui/ko.py`, 글꼴은 맑은 고딕). RMSE·Lag·Peak Error, roll/pitch/yaw, Expressive/Neutral, data_kind 값(computed/mock/simulated/measured)은 과제·문서와 같게 원어로 둔다. 용어 설명은 표 머리글·버튼에 마우스를 올리면 나온다(`ko.GLOSSARY`).
- 결과 저장 위치: `results/lab/<시각>_<sim|robot>_<R1|R2|R3>/runs/<번호>_<시행>/`, 보고서 자료는 `results/lab/exports/<시각>_report/`
- MuJoCo는 이 GUI 전용 로컬 daemon을 쓴다(127.0.0.1:8017, `SdkBackend("sim")`의 연결 확인 절차를 모두 거침).
  - MuJoCo에서 처음 재생·실행하면 daemon이 자동으로 뜬다(약 10 s, viewer 창이 열림).
  - 연결 직후 sleep 자세에서 rest로 가는 기동 램프가 돈다(`safety.startup`).
  - 실험 탭 `MuJoCo 닫기`를 누르거나 창을 닫으면 daemon도 멈춘다.

## 2. 화면

| 탭 | 있는 것 |
|---|---|
| ① 모션 | 모션·변형 선택, `내보내기...`. 왼쪽 카드: 무엇을 하는 모션인지, 길이, 애니메이션 원리, 기대하는 느낌(Valence/Arousal = **설계 목표, 측정 아님**). 오른쪽 탭: 위치 / 속도(computed), Expressive vs Neutral, E/N 나란히 영상(§2.2), 설정값(키프레임별 시간·보간·값). 아래: `▶ MuJoCo 재생`, `▶ Expressive → Neutral`, `▶ E/N 나란히 영상`(MuJoCo, 기록 안 함), `■ 정지`(MuJoCo·실제 로봇), `▶ 실제 로봇 재생`(R2 시행 1개, measured 기록; INIT 대기일 때만, 옆에 로봇 상태, 연결 전이면 로봇 상자를 여는 링크), 초기 정책 결과 한 줄 |
| ② 실험 | 위: `▶ 실행 (MuJoCo / 실제 로봇)`(실행할 곳을 버튼에 표시), `▶▶ 모두 실행`(R1·R2, 실제 로봇 제외), `■ 정지`, `결과 보기 →`, `중단 해제`(R3 이상 뒤에만) + 상태 한 줄(백엔드 상태 · 실행 중 경과 · 버튼이 꺼진 이유). 왼쪽: 백엔드(MuJoCo / 실제 로봇), 실험(동작 확인 R1 · 표현 모션 R2 · 한계 시험 R3와 조건; R1 진폭은 직접 입력 가능), 시행 목록(#, 시행, 속도 비, 관절 여유, 정책, 상태), 메모 한 줄. 오른쪽: 실시간 그래프 1개(주 채널 명령값 vs 측정값) + 기록 |
| ③ 결과 | 세션 목록과 `불러오기`, `다른 폴더 불러오기`, 세션별 시행 트리(체크로 고르기), 데이터 출처 띠와 섞임 경고, **핵심 지표**(시행, data_kind, RMSE (지연 포함), Peak (지연 포함), 지연 Lag (ms), 진폭비: 각 시행의 주 채널), 그림 5개(주 채널, R1 진폭비, R3 단계 비교, 한계 지도, Expressive vs Neutral; 각각 아래에 표), `보고서 자료 내보내기` 하나 + `폴더 열기` |

- **로봇 상자는 창 위쪽, 탭 위**에 있다(2026-11-13, 사용자 결정 "1–6 모두"): IP · 포트 · 연결 · Wake-up · 토크 OFF · 연결 끊기 · 새로고침과 로봇 상태가 한 줄.
  처음부터 떠 있고(사용자 결정 "디폴트로 떠있게"), 연결된 동안과 실험 탭 백엔드가 `실제 로봇`일 때는 숨길 수 없으며, 그 밖에는 오른쪽 위 `로봇 상자` 버튼으로 숨기거나 다시 연다. 상자는 하나이고
  실험 탭의 처리 코드를 그대로 쓴다(`ExperimentTab.release_robot_panel`, `RobotPanel.use_wide_layout`). 버튼 클릭 = 승인은 그대로다.
- 지표 이름은 표·그림·실제 로봇 메시지에서 하나로 쓴다(`results.METRIC_LABELS`): `RMSE (지연 포함)`, `Peak Error (지연 포함)`, `지연 Lag (ms)`, `Lag r²`,
  `지연 보정 RMSE`(= 지연을 뺀 동작 모양의 오차, R3에서는 진폭 대비 %), `정지 중 떨림 RMS`, 측정 곡선은 `측정값`.
- 결과 탭 `R1 진폭비`: R1 시행의 명령 진폭 vs 진폭비(회전 deg · z mm · 안테나 deg 패널, 점 = 시행, 선 = 같은 진폭 평균). `한계 지도`: 확정 모션 8개와
  R3 D 사다리(A 20°)의 요구 Stewart 속도 비 × 최고 관절 가속(log-log, computed, `experiments.limit_points`, 처음 열 때 약 1초 계산)에
  체크한 시행 중 실제 로봇에서 실행한 것(원)과 R3에서 무너진 단계(X, 점선 십자)를 겹친다. 초기 정책 속도 상한 0.5는 빨간 점선.
- R3 그림은 사다리 하나(첫 행의 바꾼 값·고정값)만 그린다. 다른 사다리 시행은 제목에 개수만. 패널 7개(지연, 지연 보정 RMSE %, 진폭비,
  Overshoot %, 정지 중 떨림 RMS, Peak Error, 정착 시간) + 범례 칸. 점 = 시행, 선 = 같은 단계 평균.
- 모션 탭 `효과음` 줄(2026-11-14, 사용자 결정 "로봇 스피커로"): 출력 `로봇 스피커`(GUI 기본) / `노트북 스피커` / `끄기`, `시각 보정`(ms),
  `♪ 소리 듣기`(노트북). Expressive 4개의 큐(aha 0.85 s, success 0.3 s, failure 0.2 s, boredom 4.9 s)를 실행기 tick에 맞춰 낸다(`reachy_motion/sound.py`, `CueTrigger`).
  로봇 스피커는 SDK daemon REST(`/api/media/sounds/upload`, `/api/media/play_sound`), MuJoCo는 노트북 스피커일 때만. 기본값은 세션마다 끔이고
  `main()`만 로봇 스피커로 켠다(테스트는 소리를 보내지 않음). 자세한 것은 [GUI_ROBOT.md](GUI_ROBOT.md) '효과음'.
- 오른쪽 위 `? 사용법`: 팀원 가이드(`docs/TEAM_GUIDE.md`)를 창 안에서 연다(다른 .md 링크도 그 창에서).
- 모션 탭 `Expressive vs Neutral`은 비교 조건을 한국어 몇 줄로 보여 준다(같은 시작·끝, 길이, 최대 회전·이동, 회전 속도, 보간, 안테나, 소리). `설정값`은 키프레임마다 이동 시간·정지·보간·목표 자세·변화량(진폭)·최고 속도다.
- 실제 로봇 R3는 시행이 끝나면 바로 다음 단계 판정이 나온다(`robot_r1.r3_next_step_problems`, 한국어): 무너졌으면 로봇 상자에 빨간 글자, 더 짧은 단계(진폭 사다리는 더 큰 A)는 `거부`, `▶ 실행` 꺼짐. 결과 탭 R3 그림에는 멈춤 기준(빨간 점선)과 무너진 단계(세로 빨간 선)가 있다. 결과 목록은 사다리 순서다.
- 실행할 수 없는 버튼은 꺼지고 이유가 상태 줄에 나온다. 예: "모든 시행이 초기 정책 밖입니다 (…)", "사다리 값 '1.0, abc'을(를) 읽을 수 없습니다 …", "로봇 상자에서 '연결'을 누르세요". 거부된 시행은 표의 '정책' 칸에 마우스를 올리면 이유가 나온다.
- 핵심 지표의 Lag는 순수 지연 맞춤의 r2가 0.9 미만이면 `378 (r² 0.38)`처럼 r2를 붙인다(그 값은 참고만).

### 2.2 E/N 나란히 영상 (모션 탭)

`reachy-motion video` 명령과 같은 영상을 GUI 안에서 만들고 본다. 왼쪽 Expressive, 오른쪽 Neutral이 같은 시간축으로 움직이고, 아래 표에 길이·예상 V/A(설계 목표)·끝 오차(sim)·최대 명령-시뮬 차(sim)·의도가 나온다.

- **만드는 방법**: daemon 없이 SDK의 MuJoCo 모델로 50 Hz 명령을 시뮬레이션 시간으로 다시 재생해 그린다(`sim_video.render_pair`, data_kind `simulated`, 로봇 아님).
  - 렌더링은 **별도 프로세스**(`python -m reachy_motion.gui.video`)에서 돈다. MuJoCo의 OpenGL과 계산이 GUI 프로세스와 50 Hz 실행기 밖에 있다.
  - 두 변형 모두 초기 정책을 통과해야 만든다(통과 못 하면 버튼이 꺼지고 이유가 나온다).
- **걸리는 시간**: 이 PC에서 모션 하나 10–12 s.
- **다시 만들지 않음**: 두 변형의 spec 다이제스트로 이미 만든 영상을 찾아 바로 보여 준다. `results/lab/videos/`를 먼저 보고, `reachy-motion video`가 WebP로 만든 `results/phase3_sim/videos/`도 찾는다. 모션 파일을 고치면 다이제스트가 달라져 새로 만든다.
- **재생**: Qt 기본 기능(QMovie)으로 WebP를 재생한다(추가 라이브러리 없음). 일시정지, 처음부터, 한 프레임씩, 속도 1×·0.5×·0.25×. 탭이 안 보이면 멈춘다.
- **공유**: `브라우저로 열기`는 같은 폴더의 `index.html`(MP4 + 표)을 연다. `폴더 열기`로 MP4를 발표 자료에 넣을 수 있다.
- **실행기 주기**: 영상을 만드는 동안 MuJoCo 시행 2개를 돌려도 건너뛴 표본 0, 최대 간격 24.8·23.3 ms(혼자 돌릴 때 23–29 ms)였다. 그래서 서로 막지 않는다.

## 3. 데이터 출처 표시

| data_kind | 뜻 | GUI 표시 |
|---|---|---|
| `computed` | SDK 보간·IK로 계산한 계획값 | 시행 표·안전 검사, 모션 탭 그림 |
| `mock` | Mock 백엔드의 합성 모델 출력. 측정 아님 (테스트 전용) | 회색 글자, 그림 제목 "Mock 모델 (mock)" |
| `simulated` | MuJoCo. 마찰이 지배적이고 이 PC에서 실시간보다 느리다 | 파란 글자, 그림 제목 "시뮬레이션 (simulated, MuJoCo)" |
| `measured` | 실제 로봇 (2026-11-12부터 있음) | 초록 글자 |

- 각 시행의 data_kind는 측정 파일 이름(`present_<data_kind>.csv`)에서만 정한다. 모든 표·그림 제목·요약·내보낸 manifest에 표시한다.
- 결과 탭 위쪽 띠에 출처별 개수를 보여 준다. measured가 없으면 "실제 로봇 측정(measured) 결과 없음: 여기 보이는 값은 로봇 측정값이 아닙니다"라고 띄운다.
- 고른 시행에 **서로 다른 data_kind, 서로 다른 단계, 여러 세션, 이전 형식(sim-verify) 시행**이 섞이면 빨간 경고 띠로 알린다.
- 결과가 없으면 빈 상태 문구만 보여 준다. 예시 측정값을 만들지 않는다.
- 내보낸 `auto_summary.md`(쉬운 요약 + 자세한 요약)는 계산된 지표의 크기와 바뀐 방향만 쓴다. 원인은 쓰지 않고, 마지막 줄에 "원인을 뜻하지 않는다"를 붙인다. Lag의 r2가 0.9 미만이면 참고만 하라고 덧붙인다.
- 모션 카드는 확정 모션 8개를 짧은 한국어 문장으로 설명한다(`ko.MOTION_SUMMARY`, 모션 파일의 설명을 옮긴 것). 다른 파일이면 모션 파일의 원문 의도를 그대로 보여 준다.
- **Expressive vs Neutral의 추종 오차 지표(RMSE·Peak Error·Lag·진폭비)는 명령을 얼마나 정확히 따라갔는지만 나타낸다.** 감정 표현력이나 의도 인식률이 아니며, 그것은 사람 대상 평가로 따로 재야 한다. 이 설명은 결과 탭 E/N 보기, E/N 그림(내보낸 PNG 포함), 자동 요약, 보고서 요약에 나온다.
- Expressive vs Neutral은 두 변형 모두 같은 채널로 비교한다. 기본은 핵심 지표 표와 같은 '주 머리 축'이고, '대표 관절'(명령 진폭이 가장 큰 Stewart 관절)로 바꿀 수 있다.

## 4. 실험

공통 규칙
- 시행 하나 = 시작 전 정지 1 s + 동작 + 끝난 뒤 정지 2 s를 한 번에 기록한다(PHASE4_PLAN §7).
- 시작 전에 머리가 멈출 때까지 기다린다(0.3 s 동안 0.03° 미만, 최대 6 s). 결과는 manifest의 `connection.settle_before`에 남는다.
- 모든 시행은 엔진 검사를 거친다.
  - `prepare(spec)`: 동작 자체, 200 Hz 조밀 검사
  - `prepare_timeline`: 정지 구간을 포함한 기록 타임라인
  - 초기 정책 밖이면 표에 `거부`로 나오고 실행되지 않는다(실행 버튼이 꺼지고 이유가 상태 줄에 나온다).
- 한 번에 하나만 실행한다(MuJoCo 미리보기 포함). 실행 중에는 실행 버튼이 꺼진다.
- 정지 = 검증된 제어 정지 S1(경로를 따라 0.3 s 감속). 전송 실패·느린 전송·측정 끊김은 즉시 정지 S2(`StopPolicy`).
- 조건이 바뀌면 시행 표에서 **아직 실행하지 않은 첫 시행**이 선택된다(R3는 가장 안전한 단계부터).
- `▶▶ 모두 실행`은 R1·R2(MuJoCo)에만 있다. 이상이 하나라도 나오면 남은 시행을 취소한다.
- 메모는 다음에 실행하는 시행 폴더에 저장된다(`notes.md`, manifest `notes`).

| 단계 | 내용 (PHASE4_PLAN) | GUI 설정 |
|---|---|---|
| R1 동작 확인 | 한 축만 아주 작게: rest → 목표까지 1.0 s minjerk → 1.0 s 정지 → 1.0 s 동안 복귀. 축은 yaw·pitch·roll·z·오른쪽 안테나·왼쪽 안테나(한쪽씩). 진폭 사다리 2→5→10°(z 1→3→5 mm, 안테나 5→15→30°). GUI 기본값은 가장 큰 단계이고 축을 바꿔도 단계가 유지된다(실제 로봇에서 2°는 거의 안 움직임, [GUI_ROBOT.md](GUI_ROBOT.md)). 진폭은 직접 입력도 된다(Enter; 회전 0.1–15°, z 0.1–8 mm, 안테나 0.1–45°, `experiments.R1_MAX_AMPLITUDE`) | 축, 진폭, 방향(+/−), 반복 |
| R3 한계 시험 | pitch 끄덕임: rest → +A까지 D → 1.0 s 정지 → rest까지 D. **한 번에 한 파라미터만**: D 사다리(A 고정, 기본 A 20°, D 1.0·0.6·0.4·0.3·0.25·0.2 s) 또는 A 사다리(D 고정, 실제 로봇은 D ≥ 1 s에서 A 10°부터). 더 짧은 D(0.15, 0.1)는 MuJoCo에서 사다리 값에 직접 적는다 | 바꿀 값, 고정값, 사다리 값, 반복 |
| R2 표현 모션 | 확정 모션 8개를 파일 그대로. 기본 3회 | 모션(하나 또는 4개 모두), 변형(둘 다 / expressive / neutral), 반복 |

R3 진행 규칙
- 한 단계가 끝나면 다음 행을 **선택만** 하고 실행하지 않는다. 단계마다 `▶ 실행`을 직접 누른다.
- 첫 이상이 생기면 사다리를 멈춘다. `중단 해제`를 누르기 전에는 다음 단계가 실행되지 않는다.
  - 이상으로 보는 것: 실행 오류, 즉시 정지 S2·S3, 계획 거부, 분석 실패.
  - 실제 로봇의 다음 단계는 앞 단계에 다음 중 하나도 없을 때만 열린다(`robot_r1.R3_LIMITS`): 진폭비 < 0.8, 지연 보정 RMSE가 진폭의 15% 초과, 오버슈트가 진폭의 15% 초과, 지연(r² ≥ 0.9)이 같은 사다리 첫 단계(D 1.0, 진폭 사다리는 A 10°)보다 100 ms 넘게 늘어남, 완료 못 함·S2·S3 정지·오류. 일정한 지연(약 0.19 s)만으로는 멈추지 않는다(2026-11-13 변경). 정지 중 떨림 RMS는 표시만 한다.
  - 진폭 사다리(2026-11-13, `robot_r1.r3_amplitude_step_problems`): A ≤ 10°가 첫 단계, 더 큰 A는 같은 D·같은 안테나 방식의 바로 아래 A(기본 사다리 10·20·30)를 실측한 뒤.
    실제 로봇은 D ≥ 1 s만(A 30°·D 0.2 s = 관절 가속 3521 °/s² > aha E 2941, computed). 같은 끄덕임(A 20°, D 1.0 s)은 두 사다리에 함께 쓰인다.
- 실제 로봇 범위: D ≥ 0.3 s 후보, 0.2 s ≤ D < 0.3 s는 앞 단계를 실측한 뒤, D < 0.2 s는 실제 로봇 제외(계산·MuJoCo만). 0.25·0.2 s는 2026-11-13 추가(aha E가 이미 실제 로봇에서 낸 속도·가속 안). 실제 로봇 실행은 [GUI_ROBOT.md](GUI_ROBOT.md).

## 6. 안전·구조

- **실제 로봇**: 창 위쪽 로봇 상자의 버튼 클릭이 그 동작 하나의 승인이다(`safety/gui_approval.py`). 시행은 표의 정책 검사를 통과한 것 하나씩만, 로봇에서는 '모두 실행'이 없다. 자세한 것은 [GUI_ROBOT.md](GUI_ROBOT.md), 규칙은 CLAUDE.md 규칙 3.
- **모션 파일**: GUI는 모션 파일을 쓰지 않는다(편집 기능 없음). 모션 탭 재생 버튼은 로컬 MuJoCo 세션만 쓴다.
- **계산 로직**: MotionSpec·Planner·Safety Checker·Tracking Analyzer는 바꾸지 않았다. GUI 계층(`gui/guide.py`, `results.describe` 등)은 그 결과를 문장·표·버튼 상태로 바꾸기만 한다.
- **50 Hz 주기 보호**
  - 백엔드와 `Executor`는 백엔드마다 작업 스레드 하나에서만 돈다.
  - 실행기의 `on_tick`은 표시용 큐에 `put_nowait`만 한다. 큐가 차면 표시 표본만 버리고 tick은 버리지 않는다.
  - GUI는 100 ms마다 큐를 비운다. 실시간 그래프는 축을 고정하고 선만 다시 그린다(blit, 4 Hz, 탭이 보일 때만).
  - 상태 줄은 400 ms마다 글자만 바꾸고, 버튼은 상태가 바뀔 때만 다시 설정한다.
  - 실행 중에는 결과 탭의 무거운 다시 그리기와 불러오기를 미룬다. 지표 계산은 실행 뒤 작업 스레드에서 한다.
  - GIL 전환 간격은 1 ms다.
