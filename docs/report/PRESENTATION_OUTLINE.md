## E/N 시연 계획 (최소 3쌍, 빠짐없이 짝으로)

| 범주 | Neutral (먼저) | Expressive | 계산 속도 비 [C] |
|---|---|---|---|
| (A) 의도 | aha_recommend N | aha_recommend E | 0.020 / 0.386 |
| (B) 상태 | boredom N | boredom E | 0.017 / 0.087 |
| (C) 반응 | success N | success E | 0.023 / 0.372 |
| (C) 선택 | failure N | failure E | 0.011 / 0.096 |

- **모션 파일**: 8개 모두 있다(`motions/*.{expressive,neutral}.yaml`, draft false). Mock에서 3쌍 6개를 차례로 실행해 확인했다(2026-11-12).
- **안테나**: GUI 실행은 안테나까지 설계대로다(깨어 있는 로봇의 INIT 안테나 = 모션 파일의 rest 안테나).
- **속도**: aha E와 success E는 R3 실측 범위(속도 비 ≤ 0.22)보다 빠르다. R3 결과는 이 둘의 안전 근거가 아니고, 두 모션은 R2 실측이 근거라고 말한다.

## 라이브 시연 준비

- **사람**: 노트북 조작 1명, 로봇 옆 1명(머리 받치기·전원). 백업 영상은 노트북에서 바로 틀 수 있게 둔다.
- **실행 경로** (Motion Lab, `docs/TEAM_GUIDE.md` §8)
  - 발표 직전 한 번: GUI 실행(`run_gui.bat` / `run_gui.command` / `run_gui.sh`) → 창 위쪽 로봇 상자에서 연결 → (필요하면) Wake-up
  - 시연: ① 모션 → 모션·변형 고르기 → `▶ 실제 로봇 재생`. 클릭 1번에 모션 1번(INIT → 모션 → INIT, 모션 길이 + 정지 약 3 s).
  - 4쌍(8개)을 모두 라이브로 해도 1–2분이다.
- **장애 대비**: 연결이 한 번 실패하면 바로 영상으로 넘어간다. 발표장 Wi-Fi에서는 로봇 IP가 바뀔 수 있다(로봇 상자 IP 칸에 입력).
