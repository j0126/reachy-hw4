## 2. 안전 규칙 (실제 로봇 전에 모두 읽는다)

- **한 로봇 = 한 프로그램.** 대시보드 앱, 다른 PC, CLI로 같은 로봇을 동시에 조작하지 않는다(SDK에 잠금이 없다).
- **로봇 옆에 한 명**: 머리를 받칠 준비, 전원 스위치에 손이 닿게.
- **이상이 보이면 바로**: `■ 정지` → 머리를 손으로 받치고 `토크 OFF` → 그래도 안 되면 전원 스위치.
  이상 = 떨림, 모터가 뜨거움, 이상한 소리, 모터 오류 메시지.
- **새 조건은 MuJoCo에서 먼저**, 작고 느리게, 한 번에 한 설정만 바꾼다.
- `토크 OFF`를 누르면 머리가 내려간다. 반드시 받친다. `연결 끊기`와 창 닫기는 토크를 끄지 **않는다**.
- R3는 한 단계씩만. D 0.2 s보다 짧은 단계는 실제 로봇에서 하지 않는다(GUI가 막는다). 실제 로봇 전에 같은 사다리를 MuJoCo에서 먼저 한다.
  진폭 사다리(선택)는 실제 로봇에서 D ≥ 1 s, A 10°부터 한 단계씩만 된다(GUI가 막는다).
- 로봇은 손상 없이 반납한다.

**로봇 상자**(IP · 연결 · Wake-up · 토크 OFF · 연결 끊기 · 새로고침)는 **창 위쪽, 탭 위**에 처음부터 떠 있다. 연결 전에는 오른쪽 위
`로봇 상자` 버튼으로 숨기거나 다시 열 수 있고, 연결된 동안과 ② 실험 백엔드가 `실제 로봇`일 때는 숨길 수 없다. 그래서 ① 모션 탭에서 연결·Wake-up·`토크 OFF`를 바로 누를 수 있다. 버튼 클릭 = 그 동작의 승인.

버튼이 회색이면 위쪽 **상태 줄**에 이유가 나온다. 버튼·표 머리글에 마우스를 올리면 용어 설명이 나온다. 실제 로봇에서 실행하지 않은 이유는 로봇 상자에도 빨간 글자로 나온다.

### 4.1 준비와 연결 (10분)

1. 로봇 전원을 켜고, PC와 로봇을 같은 Wi-Fi에 둔다. 대시보드 앱에서 다른 앱(트래킹 등)을 실행하지 않는다.
2. GUI 실행(`run_gui.bat` 등) → ② 실험 → 백엔드 **실제 로봇** → 창 위쪽 로봇 상자에서 IP(지금까지 `192.168.0.15`, 다르면 고친다), 포트 `8000` → **연결**.
   (로봇 상자는 처음부터 탭 위에 있으므로 모션 탭에서 바로 연결해도 된다.)
   - 잠든 로봇(토크 꺼짐): 연결하면 지금 자세에서 토크가 켜진다(움직이지 않음). 이어서 **Wake-up**(2초 동안 INIT로, roll 20° 갔다 옴).
   - 이미 깨어 있는 로봇: 바로 `INIT 대기`가 된다.
3. 로봇 상자 상태가 **`INIT 대기 · 시행 가능 · 토크 ON · 연결 열림`**이면 준비 끝.

### 4.2 R1 동작 확인 (5분)

② 실험 → **동작 확인 (R1)** → 축 `pitch`, 진폭 `10`(기본값), 방향 `+` → `▶ 실행` (약 6초).
고개가 10° 숙였다 돌아오면 된다(pitch + = 아래, yaw + = 왼쪽). 시행이 끝나면 로봇 상자에 `시행 끝 · 진폭비`가 나온다.
2°는 거의 안 움직인다(정상, 4.0).
진폭은 목록(회전 2·5·10°, z 1·3·5 mm, 안테나 5·15·30°)에서 고르거나 **직접 입력**하고 Enter: 회전 0.1–15°, z 0.1–8 mm, 안테나 0.1–45°.
1·3·5·7·10°처럼 여러 진폭을 재면 결과 탭 **`R1 진폭비`** 그림에 작은 명령일수록 덜 움직이는 곡선(데드밴드)이 그려진다.

### 4.3 R2 Expressive / Neutral 짝 (20분, 촬영)

- **① 모션 탭**에서 모션과 변형(Neutral → Expressive)을 고르고 **`▶ 실제 로봇 재생`** (클릭 1번 = 1번 실행, INIT → 모션 → INIT).
  실험 탭 R2 표에서 골라 `▶ 실행`해도 같다.
- 순서: aha N → aha E → boredom N → boredom E → success N → success E → (시간이 되면) failure N → failure E
- 결과는 자동으로 `results/lab/<시각>_robot_R2/`에 저장되고 결과 탭에 들어간다.
- **효과음**: Expressive 4개 모두 로봇 스피커에서 소리가 난다(모션 탭 `효과음: 로봇 스피커`, GUI 기본). aha·success는 밝게 올라가고,
  failure·boredom은 낮게 내려가며 작다(boredom은 아주 작은 한숨). Neutral은 소리 없음.
  처음 한 번 소리가 나는지 확인하고, 안 나면 `노트북 스피커`로 바꾼다. 소리가 모션보다 먼저 들리면 `시각 보정`을 +로(예: +100 ms).
  자세한 것: [GUI_ROBOT.md](lab/GUI_ROBOT.md) '효과음'.

### 4.4 R3 한계 시험 (20분, 촬영) — 과제의 핵심

0. 먼저 백엔드 **MuJoCo**로 같은 사다리를 끝까지 해 본다(사다리 값에 `0.15, 0.1`을 더 넣어도 된다).
1. ② 실험 → **한계 시험 (R3)** → 바꿀 값 `시간 D (A 고정)`, 고정값 `20 deg`, 사다리 `1, 0.6, 0.4, 0.3, 0.25, 0.2`(기본값)
2. 표에서 `D 1 s` → `▶ 실행`. 끝나면 다음 단계(D 0.6)가 **선택만** 된다. 결과(진폭비·Peak·Lag)를 확인하고 `▶ 실행`.
3. 0.4 → 0.3 → 0.25 → 0.2도 같은 방법으로 한 단계씩.
4. 시행이 끝나면 바로 판정이 나온다. **무너졌으면** 로봇 상자에 빨간 글자로 `R3 사다리 끝 — D … s에서 추종이 무너짐: 이유`가 나오고,
   더 짧은 단계의 상태가 `거부`(빨강)로 바뀌며 `▶ 실행`이 꺼진다. 그 단계가 **추종이 무너진 지점**이고, 그것이 결과다.
   기준 안이면 `다음 단계 가능`이 나온다.
   - 거부 기준(앞 단계): 진폭비 < 0.8, 지연 보정 RMSE가 진폭의 15% 초과, 오버슈트가 진폭의 15% 초과, 지연(r² ≥ 0.9)이 같은 사다리 D 1.0보다 100 ms 넘게 늘어남, 완료 못 함·S2·S3 정지·오류
   - 일정한 지연(약 0.19 s)만으로는 멈추지 않는다. 지연은 D 1.0보다 **늘어날 때만**, 오차는 **지연을 뺀 뒤** 본다
     (실측 기준선 D 1.0: 진폭비 0.92–1.03, 지연 보정 RMSE는 진폭의 7–8%, 오버슈트 약 0°).
   - 떨림은 `정지 중 떨림 RMS`(정지 구간에서 직선 추세를 뺀 흔들림)로 그림·표에 나온다. 멈춤 기준은 아니다(11/13 실측 0.009–0.014° = 센서 해상도 수준).
   - D 0.25·0.2는 2026-11-13에 실제 로봇 범위에 넣었다. aha E가 이미 실제 로봇에서 낸 속도·가속 안이다(계산값: 속도 비 0.18·0.22 vs 0.386,
     관절 가속 1391·2166 vs 2941 °/s²).
5. 연결을 끊었다가 다시 연결하면 D 1.0부터 다시 한다.
6. (선택) 진폭 사다리: 바꿀 값 `진폭 A (D 고정)`, D 1.0 고정, A `10, 20, 30`. A 10°부터 한 단계씩, 앞 단계가 기준 안일 때만 다음 A가 열린다.
   무너지면 `R3 진폭 사다리 끝 — A …°에서 추종이 무너짐`이 나오고 더 큰 A는 `거부`. 실제 로봇은 D ≥ 1 s에서만(큰 A를 짧은 D로 하면 관절 가속이
   aha E가 실제 로봇에서 낸 2941 °/s²를 넘는다: A 30°·D 0.2 s = 3521 °/s², 계산값).

D 0.15 s 이하는 **MuJoCo에서만** 한다(관절 가속이 aha E보다 커서). MuJoCo 값은 simulated이고 실제 로봇 예측이 아니다.

### 4.5 끝내기

- 깨어 있는 채로 두려면 **연결 끊기**(토크 유지).
- 완전히 끝: 머리를 받치고 **토크 OFF**(머리가 내려간다) → 전원.

### 4.6 MuJoCo로 먼저 해 보기

백엔드를 **MuJoCo**(기본값)로 두고 같은 순서로 한다. 처음 실행할 때 약 10초 뒤 viewer 창이 뜬다. 결과는 `simulated`로 따로 저장된다.
실제 로봇 전 리허설이나 로봇이 없을 때 쓴다. `▶▶ 모두 실행`(R1·R2)은 MuJoCo에서만 된다.

## 9. 문제 해결

| 증상 | 이유와 할 일 |
|---|---|
| `▶ 실행`이 회색 | 상태 줄에 이유가 있다. 실제 로봇이면 연결 → Wake-up이 먼저 |
| 연결 실패 | 로봇 상자에 원인 한 줄. IP·포트(8000)·같은 Wi-Fi 확인, 대시보드 앱 끄기, `새로고침`(상태만 다시 읽음, 명령 없음). 토크가 UNKNOWN이면 머리를 받치고 대시보드나 전원으로 끈다 |
| 머리가 명령보다 덜 움직이거나 늦다 | 로봇 특성이다(정상). 2°는 거의 안 움직임. [GUI_ROBOT.md](lab/GUI_ROBOT.md) '알려진 제한' |
| R3 다음 단계가 거부됨 | 정상이다. 앞 단계가 기준을 넘었다 = 무너진 지점. 그대로 결과로 기록 |
| R1 진폭을 넣었더니 표가 비고 `R1 범위 밖` | 축별 범위(회전 0.1–15°, z 0.1–8 mm, 안테나 0.1–45°)를 넘었다. 더 큰 동작은 R2·R3 |
| 효과음이 안 난다 | 모션 탭 `효과음`이 `로봇 스피커`인지, 로봇 상자에 빨간 효과음 메시지가 있는지 본다. 로봇 스피커에서 안 나면 `노트북 스피커`로. Expressive만 소리가 있고, boredom은 원래 아주 작다 |
| 로봇 상자가 안 보인다 | 누군가 숨겼다. 오른쪽 위 `로봇 상자` 버튼으로 다시 연다(처음 실행하면 떠 있다). 연결된 동안과 실험 탭이 `실제 로봇`일 때는 항상 보인다 |
| 상태가 `정지됨 · Wake-up 또는 토크 OFF` | `■ 정지`했거나 측정이 끊겼다. `Wake-up`으로 INIT에 돌아가 계속하거나, 머리를 받치고 `토크 OFF` |
| MuJoCo가 안 뜸 | 처음엔 10초 걸린다. `MuJoCo 닫기` 뒤 다시 실행 |
| 결과 탭 빨간 경고 | 다른 data_kind·단계·세션이 섞였다. 같은 것끼리만 체크 |
| GUI가 갑자기 꺼짐 | 함께 열린 검은 창(터미널)의 오류 메시지를 캡처해 개발 담당자에게 |
| 설치가 안 됨 (macOS·Linux) | [HANDOVER.md](../HANDOVER.md) §2.4 OS별 주의 (Intel Mac은 안 됨, Linux는 apt 패키지 먼저) |
